# TokenCanvas TUI Workbench Requirements

## Summary

为 TokenCanvas 增加一个独立的终端工作台，让用户在命令行里完成 OpenAI 图片生成、配置管理、结果保存和可选预览。首版终端配置、历史和浏览器版分离，降低跨运行时存储复杂度。

---

## Problem Frame

TokenCanvas 当前是本地浏览器图片工作台，适合可视化创作、历史复用和参数调整。但用户也会在终端里组织项目文件、编辑提示词、处理参考图路径和运行自动化脚本；如果每次生成都必须切回浏览器，终端工作流会被打断。

浏览器版已经确立为本地个人工具，并且凭证、历史和预设默认保存在浏览器存储中。把首版 TUI 直接接入这些浏览器数据，会让需求从“终端工作台”膨胀成跨运行时存储同步。当前更合适的范围是先提供独立终端体验，再根据实际使用决定是否共享配置或历史。

---

## Actors

- A1. 终端创作者：在项目目录或素材目录中用终端输入提示词、选择图片路径、生成并保存结果。
- A2. 自动化使用者：希望在脚本、批处理或一次性命令中复用同一套图片生成能力。
- A3. 后续实现者：需要明确 TUI 与浏览器版的边界，避免计划阶段重新发明产品行为。

---

## Key Flows

- F1. 首次终端配置
  - **Trigger:** 用户第一次启动终端工作台，或本地终端配置缺失。
  - **Actors:** A1
  - **Steps:** TUI 引导填写 OpenAI API key、模型和默认生成参数；用户确认保存；TUI 返回可生成状态。
  - **Outcome:** 终端本地配置可供后续 TUI 和命令模式复用，不依赖浏览器 localStorage。
  - **Covered by:** R1, R2, R4

- F2. 交互式生成
  - **Trigger:** 用户启动 TUI 并进入创作界面。
  - **Actors:** A1
  - **Steps:** 用户输入 prompt，选择文生图、图生图或 mask 模式，填写参考图和 mask 路径，调整参数并执行生成。
  - **Outcome:** 结果图片保存到用户指定或默认输出目录，TUI 展示状态、输出路径、错误恢复建议和可选预览。
  - **Covered by:** R3, R5, R6, R7, R8

- F3. 脚本友好的直接生成
  - **Trigger:** 用户不需要打开完整 TUI，只想从命令行传入 prompt、参数和文件路径。
  - **Actors:** A2
  - **Steps:** 用户运行直接生成命令；命令读取终端本地配置和传入参数；生成完成后打印机器可读或人可读的结果摘要。
  - **Outcome:** 自动化场景无需交互即可生成图片，并与 TUI 使用同一套终端本地配置。
  - **Covered by:** R5, R6, R9

- F4. 结果复查和预览
  - **Trigger:** 用户生成完成后想确认图片内容或继续使用输出文件。
  - **Actors:** A1
  - **Steps:** TUI 展示最近结果；如果当前终端支持图片协议，可内联显示缩略预览；如果不支持，提供稳定输出路径和外部打开动作。
  - **Outcome:** 预览能力增强可用体验，但不成为生成成功的前提。
  - **Covered by:** R7, R8, R10

---

## Requirements

**Terminal product shape**
- R1. TUI 必须是 TokenCanvas 的终端工作台，而不是浏览器版的远程控制面板。
- R2. TUI 首版必须使用独立的终端本地配置和历史，不读取或写入浏览器 localStorage、IndexedDB 或浏览器预设。
- R3. TUI 必须覆盖 TokenCanvas 的核心图片生成模式：文生图、图生图、多参考图和 mask 编辑。
- R4. TUI 必须提供首次配置和后续编辑配置的流程，至少覆盖 API key、模型和默认生成参数。

**Generation and output**
- R5. TUI 和直接生成命令必须复用同一套生成语义：prompt、模型、尺寸、数量、质量、输出格式、背景、压缩、参考图和 mask。
- R6. 结果图片必须保存为本地文件，并在完成后显示可复制的输出路径。
- R7. 生成中、成功、失败、取消和超时状态必须在终端里清楚表达；失败时要给出用户可执行的恢复建议。
- R8. 终端图片预览必须是可选增强：支持时可显示内联预览，不支持时不能影响生成、保存和后续操作。

**Command and automation**
- R9. 除交互式 TUI 入口外，首版还必须保留脚本友好的直接生成入口，便于自动化和批处理。
- R10. TUI 最近结果历史必须与浏览器历史分离；首版只需要支持终端侧最近结果复查，不要求完整复刻浏览器历史/预设体验。

---

## Acceptance Examples

- AE1. **Covers R2, R4.** Given 浏览器版已经保存过 API key，when 用户第一次启动 TUI，then TUI 仍然要求配置终端本地凭证，而不是读取浏览器存储。
- AE2. **Covers R3, R5, R6.** Given 用户在 TUI 中选择图生图并填写多个参考图路径，when 生成成功，then 输出文件被保存到本地路径，结果摘要包含模型、模式和输出文件位置。
- AE3. **Covers R7, R8.** Given 当前终端不支持图片内联协议，when 图片生成成功，then TUI 显示输出路径和外部打开动作，不把“无法内联预览”当作生成失败。
- AE4. **Covers R9.** Given 用户在脚本中运行直接生成命令，when 参数完整且终端配置有效，then 命令不进入交互式界面也能完成生成并输出结果摘要。
- AE5. **Covers R10.** Given 用户在 TUI 中生成了一张图片，when 用户打开浏览器版 TokenCanvas，then 浏览器历史不会自动出现该终端结果。

---

## Success Criteria

- 终端用户可以不打开浏览器完成一次真实图片生成，并清楚知道结果文件在哪里。
- 终端 TUI 对文生图、图生图和 mask 编辑的行为与浏览器版核心语义一致。
- 配置、历史和预设边界清楚，后续计划不需要重新判断是否要同步浏览器存储。
- 终端图片预览在支持协议的终端里提升体验，在不支持协议的终端里不降低可靠性。
- 下游 `/ce-plan` 可以直接围绕 TUI 入口、配置、生成、输出、预览和测试策略展开，不需要补充产品范围。

---

## Scope Boundaries

- 不共享浏览器版 localStorage、IndexedDB、历史或预设。
- 不把 TUI 做成浏览器版 UI 的完整复制；首版聚焦终端生成工作流。
- 不要求所有终端都能内联显示图片。
- 不实现完整图片编辑器、画布级 mask 绘制、图层系统或节点工作流。
- 不实现多人部署、后端密钥托管、云同步或远程任务队列。
- 不把批量任务系统作为首版主路径；直接生成命令只需支撑脚本化单次生成。

---

## Key Decisions

- 使用 Ink 系生态作为首选 TUI 方向：它符合当前 React/TypeScript 心智，适合构建交互式终端界面。
- 采用配置和历史分离策略：终端工作台先拥有自己的本地配置和最近结果，避免跨浏览器存储同步。
- 图片预览是渐进增强：终端图像协议支持度不一致，因此输出路径和外部打开动作是可靠主路径。
- 交互式 TUI 与直接生成命令并存：前者服务个人创作，后者服务自动化和脚本集成。

---

## Dependencies / Assumptions

- 本地环境需要可运行 Node.js、pnpm 和当前项目依赖。
- 用户会提供有效 OpenAI API key，并接受其保存在终端本地配置中。
- 终端图片预览依赖用户使用的 terminal emulator；支持能力需要运行时检测或用户显式开启。
- TUI 输出文件默认保存在本机文件系统，用户需要有目标目录写入权限。
